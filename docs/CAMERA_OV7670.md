# Камера OV7670 (та, что на фото)

Это **не** ESP32-CAM (OV2640). Синяя плата **OV7670** без FIFO-памяти: 8 линий данных + синхра + I2C.

## На контроллер гроубокса — нельзя

На том же ESP32 уже заняты GPIO под реле, DHT, почву, ШИМ, поплавок.  
OV7670 просит примерно: D0–D7, PCLK, VSYNC, HREF, XCLK, SDA, SCL, 3.3V, GND.  
Плюс кадр QVGA ~150 КБ в RAM — у обычного ESP32 DevKit без PSRAM это ломает прошивку гроубокса.

**Вывод:** камеру сажаем на **второй ESP32**, в админке гроубокса только URL (`camIp`).

## Как правильно

| Вариант | Оценка |
| --- | --- |
| **ESP32-CAM (OV2640)** | Лучше: JPEG, PSRAM, уже задумано в `/photo` |
| Второй ESP32 + этот OV7670 | Можно, картинка слабая, много проводов, без FIFO часто срыв кадра |
| Arduino UNO + OV7670 | Ещё хуже, не для Wi‑Fi |

## Пины модуля (с твоей платы)

`3.3V` `GND` `SCL` `SDA` `VS` `HS` `PCLK` `D0`…`D7` `RESET` `PWDN` (+ `HREF`/`HCLK` как на шелкографии).

Питание **только 3.3 V**. 5 V убьёт матрицу.

Пример на втором ESP32 DevKit (не на гроубоксе):

| OV7670 | ESP32 |
| --- | --- |
| 3.3V | 3.3V |
| GND | GND |
| SCL | 27 |
| SDA | 26 |
| VS (VSYNC) | 25 |
| HS / HREF | 23 |
| PCLK | 22 |
| XCLK / HCLK | 21 |
| D0–D7 | 35,34,39,36,19,18,5,4 |
| RESET | 3.3V через 10 кОм или GPIO |
| PWDN | GND |

Скетч-заготовка: [`firmware/cam_ov7670/`](../firmware/cam_ov7670/README.md).

В гроубоксе (дашборд / Telegram): поле **ESP32-CAM** = `http://IP-камеры`  
`/photo` шлёт эту ссылку. С улицы IP не откроется — только в LAN или через тот же трюк, что ntfy (камера сама постит кадр наружу — отдельная задача).
