# GrowBox — роадмап

Актуально на **2026-08-12**. Железо: ESP32 `9C37F6641D44`, прошивка **v6.3.4**, пульт **v6**, канал ntfy за NAT.  
Home Assistant дома нет и не планируется как обязательный путь.

Как пользоваться: выбери **эпик + номер задачи**. Каждую задачу можно делать отдельно и сразу пушить.

---

## Сейчас работает

| Канал | Состояние |
| --- | --- |
| Дашборд LAN `192.168.1.11` / `growbox.local` | да |
| Telegram | если заданы token/chat |
| ntfy + пульт https://jotalbot.github.io/GrowBox/remote.html | да |
| OTA по HTTPS | да (6.3.3+ не крутит одну и ту же прошивку по кругу) |
| Heartbeat | раз в 60 сек |
| Ручные режимы реле | сразу применяются |
| DHT22 / DS18B20 / почва | **нет данных** (DHT −127, почва s1Ok=0) |

Ограничения, от которых пляшем:

1. Входящий порт на ESP не открыть — только исходящие HTTPS (ntfy, Telegram, raw GitHub).
2. Нет всегда включённого сервера дома — HA только как опция «когда появится малина».
3. Секреты (топик/ключ) нельзя класть в публичный GitHub Pages.
4. Скетч огромный (HTML в `.ino`) — любые правки дашборда рискованные по размеру прошивки.

---

## Принципы следующих итераций

- Сначала **датчики и безопасность**, потом красота.
- Пульт = основной UI с улицы; LAN-дашборд не ломаем.
- Каждая прошивка: номер `6.3.x` / `6.4.x`, `version.json`, OTA одной командой `ota <url>`.
- Не включать «Автопрошивку» на коробке, пока сами не скажем.
- Не светить ntfy-топик и ключ в Issues/чатах.

## Эпик A — Датчики (фундамент)

Без этого графики и алерты врут.

### A1. Диагностика DHT22
**Зачем:** температура/влажность/VPD сейчас «нет DHT».  
**Сделать:** на дашборде и в ntfy-статусе сырой код ошибки (timeout / NaN / checksum), счётчик неудачных чтений подряд, кнопка «тест DHT». Проверить провод GPIO4, подтяжку 4.7–10 кОм, питание 3.3 vs 5 В.  
**Файлы:** `Growbox_CriticalKush_V6.ino` (чтение DHT), `statusJson`, пульт.  
**Оценка:** 0.5–1 день + физика на месте.  
**Риск:** низкий.

### A2. Почва ADC и калибровка с телефона
**Зачем:** `s1Ok/s2Ok/s3Ok = 0` — сырьё вне 100…4000 или датчики не воткнуты.  
**Сделать:** слать `raw1..3` в ntfy; на пульте «сухо/мокро» как на дашборде (`/calib`). Порог «откл» сделать настраиваемым.  
**Оценка:** 0.5 дня.  
**Зависит от:** чтобы горшки реально были на GPIO 32/34/35.

### A3. DS18B20 бака
**Зачем:** вода −127.  
**Сделать:** тот же разбор ошибок OneWire, адрес датчика в статусе, проверка GPIO27 + 4.7 кОм.  
**Оценка:** 0.5 дня.

### A4. Время и «день цикла»
**Зачем:** день всегда 1, пока NTP/метка не живут.  
**Сделать:** на пульте «сбросить день»; в статусе `ntpOk`, `cycleStart`.  
**Оценка:** 2–3 часа.

## Эпик B — Пульт (то, чем пользуешься каждый день)

### B1. Карточка «как дашборд» (часть уже в v6)
Почва, день, график почвы #1 — есть. Дальше: три линии на графике, свет 0/1 вторым цветом, RH когда появится DHT.

### B2. Полив без промаха
Подтверждение «Полить #2 на 8 сек?», на пульте таймер, блокировка повторного тапа, статус `watering` из JSON (поле уже есть на `/api/data`, в ntfy — добавить).  
**Оценка:** 0.5 дня (+ крошечная прошивка).

### B3. Расписание с телефона
Вега/цвет часы, рассвет, порог почвы — сейчас только LAN-форма.  
Команды ntfy: `set vegH0=6` или JSON `{"cmd":"set","arg":"sunrise:20"}` + ответ в статусе.  
**Оценка:** 1–1.5 дня.  
**Риск:** средний (парсинг, NVS).

### B4. Офлайн-индикатор честный
Если нет heartbeat > 3 мин — красный «коробка молчит», не вечный «онлайн».  
**Только JS пульта.** Оценка: 1–2 часа.

### B5. PWA без кэша-ада
`manifest.json` + service worker с версией `v6`, кнопка «сбросить кэш». Чтобы не ловить пустые поля как на v4.  
**Оценка:** 0.5 дня.

### B6. Лог команд на пульте
Последние 20 команд и ответов (`pong`, `mode`, `ota-fail`) без простыни.  
**Оценка:** 2 часа.

## Эпик C — Алерты и «чтобы не проспать»

Каналы: Telegram (уже есть каркас) и ntfy (телефон сам покажет push, если открыть ntfy-приложение на том же топике).

### C1. Молчание коробки
Нет heartbeat 3 / 10 мин → пульт орёт. На самой коробке ничего не сделать, если она мертва.  
Опционально: бесплатный ntfy watchdog с другого места — только если появится хоть какой-то всегда-онлайн (VPS/телефон с MacroDroid).  
**Оценка:** пульт 2 часа; внешний watchdog — отдельное решение.

### C2. Климат
Жара ≥ `tempEmergency`, VPD низкий на цвете (плесень), RH ≥ 75%. Сейчас часть уже в Telegram. Вынести пороги в статус, дублировать title ntfy `alert` (пульт красит красным).  
**Оценка:** 0.5–1 день. **Нужен A1.**

### C3. Безопасность
Протечка / бак пуст / нет 220 V — только после включения флагов на дашборде (сейчас выкл, чтобы не врали).  
**Оценка:** 0.5 дня + провода.

### C4. Свет не по расписанию
Если `mLight=off` дольше N часов дня веги — алерт «свет руками выключен».  
**Оценка:** 3 часа.

## Эпик D — Надёжность прошивки

### D1. Разгрузить `.ino`
Вынести HTML дашборда в PROGMEM-файл / gzip. Сейчас прошивка толстая, ElegantOTA на старых WDT уже обходили сервисным бином.  
**Оценка:** 1–2 дня. **Риск:** высокий (регрессия UI).

### D2. Слоты OTA / размер
Проверить, что 6.3.4 + следующие фичи влезают в `default.csv`. При росте — `min_spiffs` или кастомная таблица.  
**Оценка:** 0.5 дня.

### D3. Идемпотентность команд
Повторы ntfy после ребута: для `water`/`reboot` тот же skip-stale, что для OTA. Командам дать `id`, коробка помнит lastId.  
**Оценка:** 0.5 дня.

### D4. Watchdog и HTTPS
Длинный ntfy/Telegram/OTA уже кормят WDT. Аудит всех `delay` и блокирующих GET.  
**Оценка:** 0.5 дня.

### D5. Логи по Serial / кольцо в NVS
Последние 16 событий для `/api/data` и пульта (`lastEvents[]`).  
**Оценка:** 0.5 дня.

## Эпик E — Безопасность канала

### E1. Ротация ключа
Кнопка на пульте не нужна; команда `newkey` с Telegram. Документ «если топик утёк».  
**Оценка:** 2 часа + ты меняешь топик в ntfy.

### E2. ntfy ACL / свой сервер
Публичный ntfy.sh видит метаданные. Свой ntfy на дешёвом VPS (~1–2 €) или ntfy Pro.  
**Оценка:** полдня, нужен VPS.

### E3. Не светить ключ в логе пульта
Уже почти так (v4+). Проверить, что в GitHub Actions/скриншотах ключа нет.

## Эпик F — Home Assistant (когда появится железо)

Не делать, пока нет малины / мини-ПК в той же Wi‑Fi.

### F1. REST-пакет
Уже лежит `homeassistant/growbox.yaml` под `192.168.1.11`. Правка IP, restart HA.

### F2. MQTT Discovery
Код в `MqttHa.ino` (с 6.3.2). На дашборде блок брокера.  
Нужен Mosquitto в LAN.

### F3. С улицы в HA
Tailscale или Nabu Casa на сервер HA. ESP по-прежнему только в LAN к MQTT.

## Порядок, который я рекомендую

```
A1 DHT  →  B4 офлайн-индикатор  →  B2 полив с подтверждением
    →  C2/C4 алерты  →  A2 почва  →  B3 расписание с телефона
    →  D3 идемпотентность  →  G1 камера, если будет модуль
```

HA (F) — только после покупки всегда-онлайн железа.  
D1 (распил HTML) — когда прошивка снова не влезет в OTA.

## Что не стоит делать сейчас

- Проброс порта 80/3232 роутера на ESP.
- Публичный MQTT без пароля.
- Автопрошивка с GitHub raw на каждое пуш в main.
- Переписывать всё на ESPHome (потеряем текущую логику полива/VPD/агента).
- Ставить HA в облако «чтобы было» — без LAN до коробки это лишняя сложность.
